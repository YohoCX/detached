# Tech debt

Bugs and shortcuts found after milestone 1, newest first. Features go to [BACKLOG.md](BACKLOG.md).

| Issue | Where | Notes |
| --- | --- | --- |
| A watch the OS refuses is skipped without a word | `core::watch` | On Linux a worktree under the 10,000-directory cap can still pass the user's `max_user_watches` (8,192 on older kernels): the directories past it get no watch and their edits show on activation only. On macOS each change to the watch list restarts the FSEvents stream, and events in that gap of milliseconds are lost. On Windows notify 8.2.1 reports no overflow of a folder's `ReadDirectoryChangesW` buffer, so a large burst can lose events until the next activation, and an error completion unwatches the folder for good while the watcher still lists it. |
| A chat test sometimes misses the turn's last line | `tests/chat.rs` | `a_turn_s_tools_fold_into_one_line_and_a_command_s_output_opens_on_a_click` reads the "Done in 12.4 s" item without waiting for it. Under a full `make check` on 2026-11-10 it failed once and passed alone and in three runs of its file. On 2026-11-11 it read the group's "3 actions" line while it still said 2, once: it waits for the second tool, not the third. |
| Tests that wait for a shell's output time out on a loaded CI runner | `tests/dock.rs`, `tests/terminal.rs` | `wait_until` gives a shell 10 s to start and print. On 2026-11-10 two dock tests on Windows and the wide-character test on macOS timed out once each and passed on a rerun. |
| A shell released over the bottom zone opens in the center | V7 `dock::skin` | The center's drop target lies under the whole center column, the bottom zone's included, so a shell's tab dragged and released over the Terminal app itself leaves it for a tab in the center. The dock tests drop on the sidebar for "no target". |
| libghostty-vt's C API is declared by hand | V7 `terminal::ghostty` | About 35 functions, their structs and the option and data keys are copied from the 1.0 headers, without bindgen or a layout test, so a mismatch shows up as wrong behavior, not a build error. The ABI is stable across 1.x; a 2.0 needs them checked against its headers again. |
| Linux and Windows builds need Zig 0.17 | `crates/app/build.rs`, CI | Ghostty ships libghostty-vt prebuilt for Apple only, so elsewhere the build compiles it from source with `zig` from `PATH`: a few minutes after each clean target directory unless `GHOSTTY_VT_DIR` keeps it. CI installs Zig with `mlugg/setup-zig`; the release job builds the library uncached. |
| Plan limits come from an experimental SDK call | `sidecars/claude` `info` | `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET` gives the 5-hour and weekly windows; the SDK says it will be renamed. The sidecar checks it exists and shows no limits without it. Before a session runs, a `claude` with no settings answers for about a second. |
| Themes leave syntax colors to the kit | `ui::theme` | A theme file sets the editor's background and cursor line, not its token colors: those stay the kit's highlight theme until the format takes a `syntax` block. |
| Find in Files test sometimes misses "Searching…" | `tests/search.rs` | Under a full `make check` the search can finish before the test reads the status (failed 1 of 4 runs, passes alone); the test wants a frame between batches it does not hold. |
| A theme reload leaks the old tokens | `ui::theme` | `theme(cx)` hands out `&'static Theme` to its 100-odd callers, so each loaded theme is leaked, a few KB per edit of a theme file. |
| Side-by-side diffs wrap long lines | V2 `files::diff` | The kit's split columns are half the widest line and scroll as one strip, so the right side went off screen (kit #3819). Wrapping keeps both on screen until each column can take half the viewport and scroll in sync. |
| The terminal does not compose text | V7 `terminal` | Keys reach the shell through a keystroke interceptor and the session has no input handler, so IME marked text (Chinese, Japanese) and dead keys (Option+E, E on macOS) do not compose; layouts that type characters directly (Cyrillic) work. |
| The terminal's cwd test runs on Unix only (`#[cfg(unix)]`) | `crates/app` `tests/terminal.rs` | It compares `pwd -P` with the canonical repo path; PowerShell on Windows prints the runner's temp path in another spelling. |
| The test that closing a shell which ignores the hangup ends its session runs on Unix only (`#[cfg(unix)]`) | `crates/app` `tests/terminal.rs` | It uses `trap '' HUP` and checks the Unix stop pipe; on Windows ConPTY ends the reader when its master closes, and no test covers that. |
| Native packages never started on a Windows or Linux desktop | `release.yml`, `scripts/package.sh`, `core::update::Install` | Checked from CI's files only: the exe holds its icon resource, the deb installs on a bare Ubuntu 22.04 and its binary runs, the AppImage bundles its libraries. Unchecked: the per-user NSIS install, its shortcuts and uninstall, the window on X11 and Wayland, the AppImage outside Ubuntu. The update paths (`Install::apply`) need two native releases to try: the install on Windows and from an AppImage has never been run by hand. |
| The 100,000-commit log test fails on a loaded machine | `crates/core` `git::log` tests | It asserts the stream takes under 3 s of wall time; with four worktrees testing at once (load average 33) it took 4.0 s and failed `make check` once, then passed. Loose bound or a separate benchmark. |
| Tree and Changes order is not quite `localeCompare`'s | V2 `files::tree`, `files::changes` | Case is ignored and digit runs compare by value, but punctuation sorts by code point (ICU puts `_` before `-`, `.` and digits) and accents are not folded, so `a_b`/`a-b` or `é`/`e` names can swap places. |
| A long markdown file reloaded with new text blocks a frame | V2 `files::markdown`, the kit's `TextView` | The kit lays out a whole text in one frame (kit #3695): the spike's 2,000 lines take about 300 ms. A first show goes in by 4 KB pieces, one a frame (max frame 20–40 ms); a reload with changed text replaces it at once, since feeding it again would scroll back to the top. |
| No space under a markdown file's h1 and h2 rules | V2 `files::markdown` | The rule is the heading's bottom border; the kit's list rows ignore a heading's margin and give it no wrapper, so the next block starts right under the rule (12–14 px intended). |
| Viewer line numbers are not Monaco's colors | V2 `files::code`, `ui::theme` | The kit's `Input` sets the editor style from the global theme's muted and foreground colors on every render and its setter is crate-private, so the line numbers cannot take Monaco's own colors without changing every muted text. |
| A diff reloading with new text loses its scroll | V2 `files::diff` | `DiffState::set_files` resets the viewport and the kit cannot restore one (kit #3670), so a file changed on disk scrolls back to the cursor on the next status refresh; an unchanged one is not reloaded. |
| Nested repo names hold `\` on Windows | `git::discovery` | `group\api` in the sidebar; the UI fixture test checks names and the worktree's main repo on Unix only (git there may also write a worktree's link with another spelling of the temp path), and so does the sidebar test (`tests/repos.rs`) for row names, the worktree's indent and its Hide toggle; a folder chat's turn names its repo with the platform separator (`tests/chat.rs`). |
| Core tests that run on Unix only (`#[cfg(unix)]`) | crates/core | Shell stand-ins, process groups or `/` in expected paths. `git::checkout`: the 5 hook tests; `git::pull`: post-merge hook; `git::cred_tests`: all 3 (hooks); `git::runner`: cancel and silence limit (fake ssh, `ps`, `killpg`); `git::files`: fake zed; `git::remotes`: remote URLs; `git::discovery`: walk and names; `settings`: workspaces; `accounts`: credential helper script; `forge`: fake `ssh -G`; `env`: zsh login shell (3); `selftest` (2); `update`: the AppImage replace (file mode 755) and `latest-json.sh` (`sh` and `jq`, as the release job on Linux). |
| Token pull not checked against GitHub or from the Finder-started bundle | accounts, `make build` | Same code path as the GitLab check; run once with a GitHub PAT. |
