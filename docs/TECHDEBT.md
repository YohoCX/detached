| A defined process on Windows answers ConPTY by rote and ends a second late | `core::processes`, `core::proc::pty`, `kernel::proc` | A definition runs on a ConPTY as `cmd /C <file>.cmd` started in the script's own folder, the file `cd /d` to the definition's folder (quoted, `%` doubled) and then the command as its one line, so no path reaches cmd's command line; since portable-pty quotes arguments as the C runtime reads them and cmd does not: cmd expands every variable itself, `%CD%` and `%RANDOM%` included, so a value holding `&` or `(` is parsed again as in any batch file, and a literal `%` is written `%%`; its tests are `#[cfg(windows)]`. The kernel's stop and restart tests find the run with `pgrep` and are `#[cfg(unix)]`, as is the core test of Stop reaching a `nohup` child. ConPTY's own escapes are stripped from the log like any other, and blank lines it adds may stay. |
