# Tech debt

Bugs and shortcuts found after milestone 1, newest first. Features go to [BACKLOG.md](BACKLOG.md).

| Issue | Where | Notes |
| --- | --- | --- |
| Themes leave syntax colors to the kit | `ui::theme` | A theme file sets the editor's background and cursor line, not its token colors: those stay the kit's highlight theme until the format takes a `syntax` block. |
| Find in Files test sometimes misses "Searching…" | `tests/search.rs` | Under a full `make check` the search can finish before the test reads the status (failed 1 of 4 runs, passes alone); the test wants a frame between batches it does not hold. |
| A theme reload leaks the old tokens | `ui::theme` | `theme(cx)` hands out `&'static Theme` to its 100-odd callers, so each loaded theme is leaked, a few KB per edit of a theme file. |
| Side-by-side diffs wrap long lines | V2 `files::diff` | The kit's split columns are half the widest line and scroll as one strip, so the right side went off screen (kit #3819). Wrapping keeps both on screen until each column can take half the viewport and scroll in sync. |
| The terminal does not compose text | V7 `terminal` | Keys reach the shell through a keystroke interceptor and the session has no input handler, so IME marked text (Chinese, Japanese) and dead keys (Option+E, E on macOS) do not compose; layouts that type characters directly (Cyrillic) work. |
| Wide characters can shift a terminal row | V7 `terminal::view` | A row is one `StyledText` in the mono font, so a CJK glyph or emoji whose advance is not two cells moves the rest of its row; painting cell by cell fixes it. |
| The terminal's cwd test runs on Unix only (`#[cfg(unix)]`) | `crates/app` `tests/terminal.rs` | It compares `pwd -P` with the canonical repo path; PowerShell on Windows prints the runner's temp path in another spelling. |
| Native packages never started on a Windows or Linux desktop | `release.yml`, `scripts/package.sh`, `update::Install` | Checked from CI's files only: the exe holds its icon resource, the deb installs on a bare Ubuntu 22.04 and its binary runs, the AppImage bundles its libraries. Unchecked: the per-user NSIS install, its shortcuts and uninstall, the window on X11 and Wayland, the AppImage outside Ubuntu. The update paths (`Install::apply`) need two native releases to try. |
| The AppImage replace and `latest-json.sh` tests run on Unix only (`#[cfg(unix)]`) | `crates/app` `update` tests | The first checks the file mode 755, which Windows lacks; the replace runs on Linux only. The second runs the script with `sh` and `jq`, as the release job does on Linux. The macOS bundle swap, the NSIS run and the relaunch have no automated test: they are checked by hand from the previous native release. |
| The 100,000-commit log test fails on a loaded machine | `crates/core` `git::log` tests | It asserts the stream takes under 3 s of wall time; with four worktrees testing at once (load average 33) it took 4.0 s and failed `make check` once, then passed. Loose bound or a separate benchmark. |
| `refresh_all` loses a call made while it lists the repos | `crates/app` `store::refresh_all` | `again` is cleared when the listing returns, so a repo added on disk just before the call is missed until the next refresh. Seen in V4's UI test, which now seeds its repo before boot; fix: clear `again` before `list_repos` starts. |
| Tree and Changes order is not quite `localeCompare`'s | V2 `files::tree`, `files::changes` | Case is ignored and digit runs compare by value, but punctuation sorts by code point (ICU puts `_` before `-`, `.` and digits) and accents are not folded, so `a_b`/`a-b` or `é`/`e` names can swap places. |
| A long markdown file reloaded with new text blocks a frame | V2 `files::markdown`, the kit's `TextView` | The kit lays out a whole text in one frame (kit #3695): the spike's 2,000 lines take about 300 ms. A first show goes in by 4 KB pieces, one a frame (max frame 20–40 ms); a reload with changed text replaces it at once, since feeding it again would scroll back to the top. |
| No space under a markdown file's h1 and h2 rules | V2 `files::markdown` | The rule is the heading's bottom border; the kit's list rows ignore a heading's margin and give it no wrapper, so the next block starts right under the rule (12–14 px intended). |
| Viewer line numbers are not Monaco's colors | V2 `files::code`, `ui::theme` | The kit's `Input` sets the editor style from the global theme's muted and foreground colors on every render and its setter is crate-private, so the line numbers cannot take Monaco's own colors without changing every muted text. |
| A diff reloading with new text loses its scroll | V2 `files::diff` | `DiffState::set_files` resets the viewport and the kit cannot restore one (kit #3670), so a file changed on disk scrolls back to the cursor on the next status refresh; an unchanged one is not reloaded. |
| Nested repo names hold `\` on Windows | `git::discovery` | `group\api` in the sidebar; the UI fixture test checks names and the worktree's main repo on Unix only (git there may also write a worktree's link with another spelling of the temp path), and so does the sidebar test (`tests/repos.rs`) for row names, the worktree's indent and its Hide toggle. |
| Core tests that run on Unix only (`#[cfg(unix)]`) | crates/core | Shell stand-ins, process groups or `/` in expected paths. `git::checkout`: the 5 hook tests; `git::pull`: post-merge hook; `git::cred_tests`: all 3 (hooks); `git::runner`: cancel and silence limit (fake ssh, `ps`, `killpg`); `git::files`: fake zed; `git::remotes`: remote URLs; `git::discovery`: walk and names; `settings`: workspaces; `accounts`: credential helper script; `forge`: fake `ssh -G`; `env`: zsh login shell (3); `selftest` (2). |
| Token pull not checked against GitHub or from the Finder-started bundle | accounts, `make build` | Same code path as the GitLab check; run once with a GitHub PAT. |
