# Antigravity ACP and unified provider modes

Decided on 2026-11-25, from the `agy 1.5.17` protocol spike and pre-merge review.

- **Built-in ACP CLI:** Antigravity runs directly through the user's `agy acp` (`Launch::AcpCli`), with no external adapter in the catalog, `min_cli` 1.5.0, login `agy acp --login`, and off by default (`"agents": {"antigravity": true}`). The Adapters card and Adapter row appear only for providers with a separate adapter.
- **Unified modes, efforts and tool verbs:** `core::backend::Mode` (`Auto`, `Edits`, `Plan`, `Ask`, `Full`) uses Claude's access labels (`Auto`, `Edits`, `Plan`, `Manual`, `Full access`) across all providers; each backend translates canonical ids to its wire ids at the seam, and legacy saved wire ids normalize on read. ACP `thought_level` and `reasoning_effort` normalize to `effort` (`Low`, `Medium`, `High`, `Extra`, `Max`).
- **Full access via CLI flag (`FullMode::{Wire, CliFlag}`):** `agy acp` has no ACP mode id that skips all prompts, only `--dangerously-skip-permissions`. Antigravity declares `FullMode::CliFlag("--dangerously-skip-permissions")`, passed only when a trusted non-`Untrusted` session starts in `Mode::Full` (Council / Fix). Because `crates/acp` pools processes by `(program, args, env)`, a `Full` participant gets its own process isolated from ordinary chats. Switching an already-open Antigravity session into or out of `Mode::Full` is refused with a note instead of silently keeping the old mode; `Kind::Untrusted` never receives the flag.
- **Host MCP auto-allow by programmatic tool name:** each provider declares how its host MCP calls are recognized (`HostToolMatch::InputServer` for Codex, `HostToolMatch::NamePrefix` for Antigravity). Antigravity matches only `toolCall.name` (from `request_permission` or cached by `tool_call_id` from `tool_call` / `tool_call_update`) with `starts_with("mcp_<host>_")`. The `<host>` suffix (`detached-host-<8 hex>`) is random per session via `backend::random()`, so a repo's `.agents/mcp_config.json` cannot predict it. When `name` is absent in both the ask and the cache, the user is prompted normally. Pre-`initialize` `server/discover` on the host MCP route gets JSON-RPC `-32601` without breaking the single-client lock.
- **Repo trust for `.agents/`, `.agent/`, `_agents/`, `_agent/`:** `agy` discovers hooks (`hooks.json`, `plugins/*/hooks.json`), MCP servers (`mcp_config.json`), plugins, rules, workflows and skills in all four workspace roots. `ANTIGRAVITY.trust` covers all four; `trust.rs` scans `.agents/skills/**/*.md` through `front()` (no executable frontmatter in `agy` `SKILL.md`) and lists every other file under those directories whole (including `skills/*/scripts/**`), stopping at the repo/worktree root and never touching parent directories or `~/.gemini`. `Project.refused` keeps every refused layer's reason so a refusal in one layer cannot mask another. Because `.agents/` is now scanned as one opaque layer and Codex's trust globs include `.agents/skills/*/SKILL.md`, a symlink or over-1-MiB problem anywhere in `.agents/` refuses Codex as well as Antigravity (Claude stays unaffected).
- **Passive history and local delete:** `agy acp` has no `session/delete`, so Delete drops local ownership (`DeletePolicy::KeepExternal`). Past chats and transcripts are read passively from `~/.gemini/antigravity-cli/brain/<id>/.system_generated/logs/transcript_full.jsonl` (or `transcript.jsonl`), stripping `<USER_REQUEST>` wrappers and showing `PLANNER_RESPONSE` thinking, tool calls and text (`GENERIC` tool outputs are left for a follow-up in `docs/BACKLOG.md`).

Rejected:
- **`Option` for `Full` on Antigravity:** omitting `Full` would break trusted Council runs on Antigravity (which open participants in `Mode::Full`), whereas `--dangerously-skip-permissions` gives the same unattended guarantee as Claude's `bypassPermissions` and Codex's `agent-full-access`.
- **Matching host MCP tools by `title`:** `run_command` titles include user/command text and could be spoofed with `mcp_<host>_`, and sharing that check across all ACP providers would widen Codex's auto-allow surface.
- **A narrow trust glob (`.agents/skills/*/SKILL.md` only):** `agy` loads executable `hooks.json`, `mcp_config.json`, `plugins/**`, `rules/**`, `workflows/**` and `skills/*/scripts/**` from `.agents/`, `.agent/`, `_agents/` and `_agent/`, which would run unreviewed under a narrower glob.
