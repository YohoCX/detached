# CI: faster, cheaper, nothing dead

**Decided by the owner on 2026-11-18.**

An audit of the GitHub Actions runs found: Windows Check rebuilt from scratch on every red run
(~27 min), since rust-cache does not save after a failure; the Actions cache at 12.7 GB, over the
10 GB limit, so entries evicted one another; Agent running on every tag push; the wsl2 leg at 28 min.

## What was decided

- **rust-cache saves on failure and on main alone** (`cache-on-failure`, `save-if` on
  `refs/heads/main`; in `agent.yml` also not for a vetting leg at a tag). Branches restore main's
  cache and save none, so the quota holds main's entries. Check is dispatched by hand, so its cache
  is refreshed by a run on main.
- **The ghostty-vt build directory is one of rust-cache's `cache-directories`**, not an
  `actions/cache` of its own. `build.rs` keeps the library under its version, so a cached one is
  reused only at that version.
- **`concurrency` with `cancel-in-progress`** in Check and Agent; Agent's group carries its inputs,
  so agent-vet's legs do not cancel each other.
- **Every workflow reads only** (`permissions: contents: read`); the jobs that publish write.
- **Check**: a 60-minute timeout, one apt-get install, and on macOS the tests' sandboxes on
  `make ramdisk`'s RAM disk (no sudo; a failure leaves them on disk).
- **Agent**: no run on tags (`branches: ['**']`); its paths drop the missing `core/src/backend/`
  and add the kernel's panel and `adapters/adapters.json`, which the harness reads; rust-cache is
  keyed per runner image, since 22.04 and 24.04 share an OS and their C objects differ; the WSL
  step takes `CLI` and `LATEST` through `WSLENV`, not pasted into its script.
- **The wsl2 leg runs only what WSL's kernel changes**: the kernel's fake-CLI and real tests.
  `agent-ci.sh` skips acp's and core's tests inside WSL; native ubuntu-24.04 runs them.
- **Agent vetting**: the latest `claude` daily, the floor on Mondays and by hand.
- **Release has no rust-cache**: a cache saved at a tag is visible to that tag alone, so it never
  hit and only filled the quota.
- **`make check`'s second clippy lints the product**: `cargo clippy --workspace` without tests or
  test-only features. The old `-p detached-core --all-features` run linted what the workspace run
  already did, since the other crates' dev-dependencies turn on core's `testutil` and `e2e`.
- **Debug builds keep line tables only**, dependencies no debuginfo: backtraces still name lines,
  and a fresh `make check` leaves 8.1 GB in `target/debug` on macOS instead of 13 GB.
- **The toolchain is pinned** in `rust-toolchain.toml` (1.100.0, rustfmt, clippy). Locally and in
  CI rustup reads it; the workflows run `rustup toolchain install` instead of
  `dtolnay/rust-toolchain`. A bump is its own commit.

## Rejected

- **One test binary for `crates/app/tests`**: fewer links, but it breaks the rule of one test file
  per vertical that parallel work depends on.
- **Sharding the Windows tests across jobs**: more runner minutes and a cache per shard, for a
  leg the cache fix already shortens.
- **sccache**: a second cache beside rust-cache, in the same quota.
- **nextest**: a new runner and its config for a speedup that the cache fix mostly covers.
- **mold**: Linux only, and the slow leg is Windows.
