# Sessions: a workspace's work as sets of worktrees

The owner's model: a workspace holds repositories; a session is one piece of work made of managed worktrees of
some of them; a session has tabs of any kind (chats, Council, MRs, files, diffs, terminals); the left side lists
sessions. Browsing files and reading code is a core part of the product. Drafted with Fable and Astra in
the design canvas, direction "Sessions".

Decided:
- One branch name for all of a session's repositories, with a per-repository override.
- No shared parent folder for a session: worktrees stay at H6's paths (no known build reaches a sibling by `../`).
- Archive keeps everything (worktrees, changes, branches, chats) and resumes exactly; removing worktrees is separate.
- The center can be split horizontally and vertically, as in a terminal, each pane with its own tabs; the three
  dock zones and the Docs/Chats/Code filter go.
- Repositories outside a session are not in its search or its chats' reach. The app, or an agent, may suggest
  adding one; adding it opens a clean worktree in the session.
- A session may adopt existing worktrees, one owner each; a Fix's worktree stays its Fix's.
- Create session from MR opens the MR and its verified head first.
- Today's tabs and per-repository chats move to the archive.
- A new branch starts from the recipe's base by default; the base can be chosen by hand when creating a session
  or adding a repository, and an agent adding a repository may name one.

Rejected: read access to non-member repositories by default (stale main checkouts mislead an agent); sessions on
a tag or bare commit (not now).
